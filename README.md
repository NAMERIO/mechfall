# MECHFALL

MECHFALL is an original browser-based 3D `.io` hide-and-seek prototype. Hiders sample colors from the environment, reshape their bodies, and blend into the map. Hunters must expose them before the round timer expires.

It is inspired by the paint-and-hide premise of *Meccha Chameleon*, but uses original code, naming, UI, procedural characters, and a new factory arena. The `survev/` reference folder is ignored and was not modified or copied into this project.

## Quick start

Requirements: Node.js 22+ and pnpm 11+.

```bash
pnpm install
pnpm dev
```

Open <http://localhost:5173>. The API and WebSocket server run on port `3001`. Three server-controlled bots make every local match playable immediately; other browser tabs join the same room.

Production:

```bash
pnpm build
pnpm start
```

The production server hosts the compiled client and listens on `PORT` (default `3001`) and `HOST` (default `0.0.0.0`).

## Controls

| Input | Action |
| --- | --- |
| `W A S D` | Move |
| `Space` | Jump |
| Mouse | Look |
| `F` as hider | Open or close Chroma Studio |
| Left-drag in Chroma Studio | Paint directly on a body part |
| Right-drag in Chroma Studio | Orbit around your character |
| Middle-drag in Chroma Studio | Alternate camera orbit control |
| `E` in Chroma Studio | Sample an environment color |
| Mouse wheel in Chroma Studio | Change brush size |
| Left click as hunter | Tag a close, centered hider |
| `C` | Cycle standing, crouched, and blob shapes |
| `Q` | Whistle and reveal your general position |

## Architecture

```text
mechfall/
├── client/                 Three.js rendering, input, HUD, matchmaking client
│   └── src/
│       ├── main.ts         Minimal application bootstrap
│       ├── app/
│       │   └── gameApp.ts  UI state and game lifecycle
│       ├── game/
│       │   ├── InputController.ts Keyboard, mouse, and pointer lock
│       │   └── WorldRenderer.ts   Arena, avatars, camera, effects
│       ├── net/
│       │   └── GameConnection.ts  Matchmaking and WebSocket transport
│       └── styles/
│           └── index.css   Menu, HUD, overlays, and responsive rules
├── server/
│   ├── src/
│   │   ├── index.ts        HTTP API, static hosting, WebSocket upgrade/auth
│   │   ├── matchmaking/
│   │   │   └── RoomManager.ts Match tickets and room lifecycle
│   │   └── game/
│   │       ├── GameRoom.ts Authoritative ticks, rounds, bots, actions
│   │       └── physics.ts  Movement and server collision
│   └── test/game/          Server simulation tests
├── shared/
│   └── src/
│       ├── net/protocol.ts Versioned messages and shared game state
│       └── game/world.ts   Arena collision geometry and spawn points
└── survev/                 Untouched reference project (gitignored)
```

`client/dist/` and `server/dist/` are generated by `pnpm build`. Do not edit their hashed files; changes belong in `client/src/`, `server/src/`, or `shared/src/`.

The browser only sends intent: movement inputs, paint choice, shape choice, tag attempt, or whistle. The server owns positions, collision, roles, timers, tag validation, scoring, and the canonical room snapshot. This is the key boundary that makes the game multiplayer-safe instead of trusting each client.

### HTTP API

- `GET /health` — process health check
- `GET /api/status` — online players, rooms, and protocol version
- `POST /api/matchmake` — allocates a room and returns a short-lived, single-use WebSocket ticket

### WebSocket flow

1. The client calls `/api/matchmake`.
2. It connects to `/play?room=ROOM_ID`.
3. Its first message is a protocol-versioned `hello` containing the ticket.
4. The server consumes the ticket, sends `welcome`, synchronizes existing body paint, and streams authoritative snapshots at 20 Hz.
5. Input is sent at 30 Hz; the server simulation also runs at 30 Hz.

Paint strokes are sent separately from movement snapshots. The server validates and caps each player's stroke history, broadcasts incremental strokes to the room, and sends the complete paint state to late joiners.
